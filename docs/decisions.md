# Decisions — 2026-11-01

1. **Demo first.** The user explicitly selected a working demo with no API keys or paid services. No providers, bookings, payments, or deployment are enabled.
2. **Local Python + SQLite + browser JavaScript.** The only starting file was the specification. Python 3.12 is installed; Node 18 is present, but package downloads failed with DNS/network errors. The suggested Next.js/TypeScript/Prisma stack was considered. A dependency-free local stack provides the API and storage behavior without an install step. Consequence: live integrations and production serving require later work; there is no npm lockfile.
3. **Canonical JSON Schema consumed directly.** Copied the provided contract into `schemas/itinerary.schema.json`. Runtime validation interprets only the keywords present in that versioned contract. Business validation independently checks date coverage, time conflicts, sources, IDs, costs, and budget status. Consequence: extending the schema requires extending/reviewing validator support. A general library was considered but unavailable through the network.
4. **Explicit demo time zones.** Windows lacks installed tzdata. Restrict the demo to five known IANA zones and destination-local wall times, without claiming conversions. Consequence: arbitrary destination zones are out of demo scope; there is a visible zone selector and documented limit.
5. **Chat plus inspectable details and plan.** A form-only app would miss conversational revisions; chat-only hides dates and cost errors. Chat extracts a bounded set of fields; a form and confirmation summary provide corrections. Deterministic edits preserve unaffected days.
6. **Quiet editorial visual direction.** Cream, forest green, serif headings, and CSS postcard artwork. No remote fonts, stock photos, images, trackers, or external requests are needed. Mobile separates chat/details and plan into explicit tabs.
7. **Transactional revision and request caching.** SQLite write transactions serialize generation/revision checks. Expected revisions prevent lost updates; request keys plus payload fingerprints reuse duplicate results and reject changed payloads with reused keys. Cached request results cascade on trip/session deletion.
